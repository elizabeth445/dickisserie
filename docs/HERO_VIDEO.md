# Видео вступления Hero

Актуальный мастер предоставлен пользователем: `2026-11-22 22.19.55-upscaled-3x.mp4`, 3840×2160, H.264, 9.9с. Неизменённая копия — `references/hero-motion-upscaled-3x.mp4`. Предыдущий исходник 1280×720 сохранён отдельно как `references/hero-motion-original.mp4` и не используется для новых экспортов.

По последнему запросу последние две секунды исключены из всех рабочих версий. Длительность ролика на сайте — 7.9с, 190 кадров. Файл пользователя содержит апскейл 3×; дополнительная генерация продуктов и локальные пробные модели восстановления в финальный ролик не применялись.

## Версии

| Файл | Качество и применение |
| --- | --- |
| `public/assets/hero-motion-4k.mp4` | 3840×2160, примерно 15MB. Видеопоток скопирован без повторного сжатия, обрезан до 7.9с. Desktop от 1101px и планшеты с высоким DPR |
| `public/assets/hero-motion-1080.mp4` | 1920×1080, примерно 5.4MB. Из нового мастера, Lanczos downsample, H.264 CRF16. Телефоны и меньшие экраны |
| `public/assets/hero-motion-720.mp4` | 1280×720, примерно 2.4MB. Из нового мастера, H.264 CRF17. Для соединений 2G/3G |
| `public/assets/hero-motion-first.webp` | Poster 1920px, около 95KB, из первого кадра нового мастера |
| `public/assets/hero-scene-extended*.avif` и WebP | Детальная статичная фотография после вступления и для fallback |

Во всех веб-версиях удалены звук и служебные метаданные. MP4 подготовлены с fast-start. Источники не изменены. Кадры `screenshots/video-source-*.png` относятся к просмотру старого исходника; они не загружаются как анимация.

Повторный экспорт: `FFMPEG_BIN=/absolute/path/to/ffmpeg node scripts/prepare-hero-video.mjs`. FFmpeg — локальный инструмент подготовки; runtime-зависимости сайта не добавлялись.

## Поведение

- Однократный запуск, muted/playsInline. После конца — раскрытие статичной фотографии за 350ms, без повторения последних двух секунд и без автоматического цикла.
- Доступная кнопка 44×44: Pause, Play или Replay animation. Ручная пауза сохраняется при прокрутке туда и обратно.
- IntersectionObserver и visibilitychange останавливают декодирование вне Hero и в скрытой вкладке. Есть cleanup, дополнительных RAF-циклов нет.
- При reduced-motion и Save-Data видео не монтируется и не запрашивается. Изменение reduced-motion учитывается в реальном времени.
- При запрете autoplay остаётся фотография и доступен ручной Play. При ошибке видео остаётся фотография; навигация работает.
- Выбор качества выполняется один раз при загрузке, без перезапуска ролика при resize. Низкая скорость соединения имеет приоритет над размером экрана.
- Видео и фото делят общий контейнер GSAP. Маска и общее бархатное полотно неподвижны относительно документа. До 1100px сцена расположена под слоганом.

## Проверки

Локальный Google Chrome: metadata подтверждает 3840×2160 на 1440px и 1920px, 1920×1080 на 390px; duration 7.9с. Проверены autoplay, pause, offscreen pause/resume, окончание, replay, live reduced-motion, media error и запрет autoplay. Скриншоты нового качества: `screenshots/video-upgraded-{width}.png`.

Полная responsive-матрица: 320,375,390,428,768,1024,1280,1440,1600,1920px. Горизонтального переполнения нет. Функциональные проверки корзины, навигации и axe сохранены. Итоговые результаты — в локальном Playwright report.

Проверки на телефонах выполняются через Chrome mobile emulation, не на физических устройствах. Показатели декодирования относятся к конкретному локальному запуску и не являются гарантией для любой сети или устройства. Никакая обработка или публикация на сторонние сервисы не выполнялась.
